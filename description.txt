# Задача: мини-утилита для обновления программ через winget (Windows, Python + Tkinter)

## Цель
Небольшое десктопное приложение, которое показывает, какие программы на ноутбуке можно обновить через winget, и позволяет обновить все сразу или только выбранные галочками. Всё, что не обновилось, записывается в лог в формате, удобном для последующего разбора вместе с Claude.

## Ограничения
- Python 3.13, только стандартная библиотека (Tkinter, subprocess, json, threading, logging). Никаких внешних зависимостей.
- Запуск через `run.bat` (использовать `py -3 updater.py` или `pythonw`, чтобы не висело окно консоли). Положить bat рядом со скриптом.
- Права администратора НЕ требуются для запуска. Утилита работает с правами обычного пользователя.
- Один файл `updater.py` (допустимо плюс `config.json`). Код чистый, с комментариями на русском.

## Интерфейс
- Главное окно со списком (Treeview с чекбоксами): колонки «Имя», «ID», «Текущая версия», «Доступная версия», «Источник», «Статус».
- Кнопки: «Проверить обновления», «Обновить все», «Обновить выбранные», «Открыть лог». Внизу строка статуса и прогресс.
- При запуске окно автоматически проверяет список (`winget upgrade`).
- Во время обновления интерфейс не должен зависать: winget запускается в отдельном потоке, вывод обновляет статус каждой строки (ожидает → обновляется → успех / ошибка / пропущено).
- Кнопки блокируются на время работы. Параллельный запуск двух обновлений запрещён.

## Парсинг списка (слабое место, сделать аккуратно)
- У `winget upgrade` нет JSON-вывода, нужно парсить текстовую таблицу.
- Определять колонки по позициям заголовка и строки из дефисов (учитывать, что имена могут содержать пробелы и быть обрезаны символом «…»). Игнорировать строки прогресса и спиннера, а также итоговую строку «N upgrades available».
- Вызывать `winget upgrade --accept-source-agreements` и по возможности не зависеть от языка системы (искать строку из дефисов, а не слова из заголовка).
- Версии вида `< 3.14.7` или `> 2025.2.5` означают, что winget не смог точно определить версию. Показывать их с пометкой «версия не определена» и по умолчанию не отмечать галочкой.
- Источник `msstore` обрабатывать отдельно (добавлять `--source msstore` при обновлении).
- Если парсинг не удался, показать сырой вывод winget в окне и записать его в лог.

## Обновление
- Для каждой программы: `winget upgrade --id <ID> --silent --accept-source-agreements --accept-package-agreements` (для msstore добавить `--source msstore`).
- Запускать через `subprocess.run` со списком аргументов, без `shell=True`. ID брать только из распарсенного списка и валидировать (допустимы буквы, цифры, `.`, `+`, `-`, `_`).
- Сохранять код возврата и полный вывод каждой команды.
- Порядок: сначала `Microsoft.VCRedist.*`, потом остальные (некоторым пакетам нужны свежие зависимости).
- После «Обновить все» делать повторную проверку списка и показать, что осталось.
- Результат «No applicable upgrade found» (новая версия есть, но не подходит под систему) классифицировать как «не применимо», это не ошибка утилиты.

## Программы, которым нужен админ
- В колонке «Статус» показывать пометку «нужен админ». Определять двумя способами:
  1. Список в `config.json` (`admin_required`: шаблоны ID, по умолчанию `Microsoft.VCRedist.*`, `Microsoft.Edge`, `Logitech.LogiTune`).
  2. Автообучение: если установка завершилась ошибкой, похожей на отказ в правах (код возврата winget, отмена UAC, «requires administrator» в выводе), ID добавляется в отдельный файл `learned_admin.json`, и в следующий раз строка помечается заранее.
- Такие программы по умолчанию не отмечаются галочкой и не входят в «Обновить все» (в config.json можно включить обратно).
- Утилита сама не повышает права и не вызывает UAC.

## Конфиг (`config.json`)
- `exclude`: ID, которые никогда не показываются или не обновляются (например `Python.Launcher`).
- `admin_required`: см. выше.
- `include_admin_in_update_all`: false по умолчанию.
- Если файла нет, создать со значениями по умолчанию.

## Лог
- Папка `%USERPROFILE%\UpdateLogs`, один файл на день: `update-YYYY-MM-DD.log`, режим дозаписи.
- Для каждой программы запись: время, ID, версия «из → в», результат (успех / ошибка / не применимо / нужен админ / пропущено), код возврата, последние ~30 строк вывода winget.
- В конце сессии итоговая сводка: сколько обновлено, сколько не удалось и список проблемных ID.
- Кроме читаемого лога вести `failures.jsonl` (одна JSON-строка на неудачу) со всеми деталями, чтобы файл можно было целиком передать Claude для разбора.
- В лог не писать ничего чувствительного (пути пользователя допустимы, токенов и паролей утилита не использует).

## Обработка ошибок
- winget не найден: понятное сообщение в окне.
- Нет сети или истёк таймаут: таймаут на одну программу 10 минут, затем статус «таймаут» и переход к следующей.
- Программа запущена и мешает обновлению: статус «возможно, запущена, закройте и повторите».
- Любое исключение логируется, интерфейс не падает.

## Критерии готовности
1. `run.bat` открывает окно и показывает список обновлений.
2. «Обновить выбранные» обновляет только отмеченные программы, «Обновить все» все, кроме исключённых и требующих админа.
3. Статусы в таблице меняются по ходу работы, окно не зависает.
4. Неудачи видны в окне и записаны в `update-*.log` и `failures.jsonl`.
5. README на 10-15 строк: как запустить, где лог и как править config.json.
